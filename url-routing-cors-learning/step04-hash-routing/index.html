STEP 04

ハッシュルーティング

URL の # 以降は サーバーに送られない。この性質を使って、ブラウザの中だけで画面を切り替えます。

1. ミニ SPA（Single Page Application）

#/ #/users #/users/1 #/users/2 #/users?sort=desc #/nothing (404)

ページ読み込み時刻: （画面を切り替えても変わらない = リロードしていない）

ルーティングのログ

2. 仕組み

ブラウザ                                       サーバー
  │  リンクをクリック: #/users/2                    │
  │  ✗ リクエストは飛ばない                         │  （何も知らない）
  │  hashchange イベント発生                       │
  │  JS が location.hash を読んで画面を描き換える   │

  リロードした場合でも、サーバーに送られるのは # より前だけ
  │ ── GET /step04-hash-routing/ ────────────────▶ │  いつもの index.html を返すだけ
  │  JS が起動時に location.hash を読んで画面を復元  │
DevTools → Network を開いてリンクをクリックしても、リクエストが 1 件も増えない ことを確認してみましょう。

3. コード（このページで実際に動いているもの）

// ① ルート定義: パターン → 画面を作る関数
const routes = [
  { pattern: "/",          view: homeView },
  { pattern: "/users",     view: userListView },
  { pattern: "/users/:id", view: userDetailView },
];

// ② location.hash を「パス」と「クエリ」に分ける
function parseHash() {
  const raw = location.hash.slice(1) || "/";      // "#/users?sort=desc" → "/users?sort=desc"
  const [path, query = ""] = raw.split("?");
  return { path, query: new URLSearchParams(query) };
}

// ③ 照合して描画（matchRoute は STEP 3 のサーバー側と同じ考え方）
function router() {
  const { path, query } = parseHash();
  for (const r of routes) {
    const params = matchRoute(r.pattern, path);
    if (params) return render(r.view(params, query));
  }
  render(notFoundView());
}

// ④ hash が変わったとき + 最初の読み込み時に実行
window.addEventListener("hashchange", router);
router();

4. 特徴まとめ

👍 良い点サーバー側の設定が不要（静的ファイル置き場・file:// でも動く）/ リロードしても 404 にならない / 戻る・進むが効く
👎 弱い点URL に # が入って見た目が不自然 / サーバーがパスを知らないので SSR や検索エンジン対応がしにくい / 本来の「ページ内リンク (#section)」と衝突する

GitHub Pages のような「サーバーの設定をいじれない」場所でよく使われます。
