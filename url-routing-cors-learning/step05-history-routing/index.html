2. 仕組み

// ① リンクのクリックを横取りして、ページ遷移を止める
document.addEventListener("click", (e) => {
  const a = e.target.closest("a[data-link]");
  if (!a) return;
  e.preventDefault();                      // ← これがないと普通にサーバーへリクエストされる
  navigate(a.getAttribute("href"));

// ② URL だけ書き換えて（リクエストなし）、画面を描き直す
function navigate(url) {

3. ⚠ リロードするとどうなる？ ── サーバー側の「フォールバック」が必要

pushState で作った URL は ブラウザが勝手に作った URL です。その URL でリロードやブックマークからアクセスすると、ブラウザは普通に サーバーへ リクエストします。

GET /step05-history-routing/app/users/1
       ↓
サーバー「そんなファイルは無い」→ 404 Not Found   ← フォールバックが無い場合
サーバー「/app/ 以下は全部 index.html を返す」→ JS が URL を見て画面を復元 ✓
✅ フォールバックあり: /app/users/2 を直接開く ❌ フォールバックなし: /no-fallback/users/2 を直接開く

server.js での実装（静的ファイルが見つからなかったときだけ index.html を返す）:

const SPA_PREFIX = "/step05-history-routing/app/";

if (tryServeStatic(req, res, pathname)) return;        // ① 本物のファイルがあればそれを返す

if (pathname.startsWith(SPA_PREFIX)) {                  // ② 無ければ SPA の index.html を返す
  res.writeHead(200, { "Content-Type": "text/html; charset=utf-8" });
  return fs.createReadStream(SPA_INDEX).pipe(res);
}

nginx なら try_files $uri $uri/ /index.html;、Vite の開発サーバーや Netlify / Vercel では設定済み、あるいは _redirects 等で指定します。

index.html 内の CSS / JS を ./common.css のような 相対パス で書くと、/app/users/1 で開いたときに /app/users/common.css を探しに行って壊れます。絶対パス (/common.css) にしましょう。
