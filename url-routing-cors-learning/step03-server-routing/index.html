STEP 03

サーバーサイドルーティング

いちばん基本の形。URL のパスを見て、サーバーがどの HTML を返すかを決めるのがルーティングです。

1. 流れ

ブラウザ                                     サーバー (server.js)
  │  リンクをクリック: /server/items/2            │
  │ ───── GET /server/items/2 ─────────────────▶ │  ルーティングテーブルを上から照合
  │                                              │   /server            ✗
  │                                              │   /server/items      ✗
  │                                              │   /server/items/:id  ✓ → params.id = "2"
  │ ◀──── 200 OK + HTML（ページ全体）──────────── │  serverItemDetail() が HTML を生成
  │  画面を丸ごと描き直す（フルリロード）           │
  • ページ遷移のたびに サーバーへリクエスト が飛び、HTML 全体 が返ってくる
  • JavaScript は不要。<a href> と <form> だけで動く
  • どのルートにもマッチしなければ 404 を返す（これもサーバーが決める）

2. 動かしてみる

下のリンクは server.js が動的に HTML を作って返すページです。各ページに「サーバーが受け取ったリクエスト」と「生成時刻」が表示されます。

/server /server/items /server/items/1 /server/items/3 /server/items/999 (404) /server/search?q=ん

DevTools → Network を開いた状態でクリックすると、毎回 document 型のリクエストが飛んでいるのがわかります。

⚠ server.js 経由で開かれていないようです。node server.js を起動して http://localhost:3000/ から開き直してください。

3. サーバー側のコード（server.js から抜粋）

// ① ルーティングテーブル: パスのパターン → 処理する関数
const serverRoutes = [
  { method: "GET", pattern: "/server",           handler: serverHome },
  { method: "GET", pattern: "/server/items",     handler: serverItemList },
  { method: "GET", pattern: "/server/items/:id", handler: serverItemDetail },
  { method: "GET", pattern: "/server/search",    handler: serverSearch },
];

// ② パターン照合: "/server/items/:id" と "/server/items/2" → { id: "2" }
function matchRoute(pattern, pathname) {
  const p = pattern.split("/").filter(Boolean);
  const a = pathname.split("/").filter(Boolean);
  if (p.length !== a.length) return null;
  const params = {};
  for (let i = 0; i < p.length; i++) {
    if (p[i].startsWith(":")) params[p[i].slice(1)] = decodeURIComponent(a[i]);
    else if (p[i] !== a[i]) return null;
  }
  return params;
}

// ③ リクエストごとに URL を分解し、マッチしたハンドラを呼ぶ
http.createServer((req, res) => {
  const url = new URL(req.url, `http://${req.headers.host}`);  // STEP 1 と同じ URL クラス
  for (const r of serverRoutes) {
    const params = matchRoute(r.pattern, url.pathname);
    if (params) return r.handler(req, res, url, params);
  }
  serverNotFound(req, res, url);  // どれにも当たらなければ 404
});

// ④ クエリパラメーターはサーバーでも searchParams で読める

4. 特徴まとめ

👍 良い点仕組みが単純 / JS 無しで動く / 検索エンジンに強い / どの URL でもリロード・ブックマークが効く
👎 弱い点遷移ごとに画面全体を再読み込みするので、入力中の状態や JS の変数は消える / 毎回通信が発生
この「毎回フルリロード」を避けたい → ブラウザの中だけで画面を切り替える クライアントサイドルーティング（STEP 4 ハッシュ、STEP 5 History API）へ。
