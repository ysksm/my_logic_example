STEP 06

CORS の基本

ブラウザは「別のオリジンから取ってきたデータを JS で読む」ことを標準では禁止しています。それを サーバー側の許可で 解除する仕組みが CORS（Cross-Origin Resource Sharing）です。

1. オリジン = protocol + hostname + port

このページのオリジン: ／ API サーバー:

http://localhost:3000/step01/✅ 同一オリジン（パスが違うだけ）
http://localhost:4000/❌ 別オリジン（ポートが違う）← このステップで使う API
https://localhost:3000/❌ 別オリジン（プロトコルが違う）
http://127.0.0.1:3000/❌ 別オリジン（同じマシンでもホスト名の文字列が違う）
http://api.example.com❌ example.com から見て別オリジン（サブドメインも別）

判定:

2. 実験: 4 つのリクエストを送ってみる

DevTools の Console と Network も開いておくと、ブラウザが出すエラーメッセージも見られます。

A. 同一オリジン fetch("/api/hello")

同じオリジンなので CORS は関係なし。必ず読める。

B. 別オリジン・CORS ヘッダーなし /basic/no-cors

サーバーは 200 OK を返すが、Access-Control-Allow-Origin が無いのでブラウザがブロックする。

C. 別オリジン・Access-Control-Allow-Origin: * /basic/wildcard

「どこのオリジンからでも読んでいい」と宣言。公開 API 向け。

D. 別オリジン・許可リスト方式 /basic/allowlist

サーバーがリクエストの Origin ヘッダーを見て、許可リストにあればそのオリジンを返す。

3. API サーバー側のログ（サーバーには何が届いた？）

B を実行してからログを見てください。ブラウザでは「失敗」なのに、サーバーには GET リクエストが届いていて、処理もされているはずです。
CORS は「サーバーを守る仕組み」ではなく、ブラウザが「レスポンスを JS に渡すかどうか」を決める仕組みです。

4. 何が起きているか

ブラウザ (localhost:3000 のページ)                    API サーバー (localhost:4000)
  │ fetch("http://localhost:4000/basic/no-cors")          │
  │ ── GET /basic/no-cors ─────────────────────────────▶ │
  │    Origin: http://localhost:3000  ← ブラウザが自動で付ける
  │                                                      │ 処理する（ログに残る）
  │ ◀──── 200 OK ─────────────────────────────────────── │
  │       (Access-Control-Allow-Origin なし)               │
  │                                                      │
  │ ブラウザ「許可が無いので JS には渡さない」
  │ → fetch は TypeError: Failed to fetch で reject
  │ → Console に "blocked by CORS policy"
// サーバー側 (server.js) の違いはヘッダー 1 行だけ
"/basic/no-cors":   () => ({ headers: {} }),
"/basic/wildcard":  () => ({ headers: { "Access-Control-Allow-Origin": "*" } }),
"/basic/allowlist": (req) => {
  const origin = ALLOWED_ORIGINS.has(req.headers.origin) ? req.headers.origin : null;
  return { headers: origin
    ? { "Access-Control-Allow-Origin": origin, Vary: "Origin" }
    : { Vary: "Origin" } };   // Origin ごとに結果が変わるのでキャッシュに Vary: Origin を伝える
},
CORS は ブラウザだけ が守るルールです。curl http://localhost:4000/basic/no-cors のようにブラウザ以外から呼べば、普通にデータが取れます。だから「秘密のデータを CORS で守る」ことはできません。認証は別途必要です。

5. 制限されないもの

同一オリジンポリシーが止めるのは 「JS がレスポンスの中身を読むこと」 です。次のものは昔から別オリジンでも使えます。

  • <img src>, <script src>, <link rel=stylesheet>, <iframe> での読み込み（表示はできるが、JS で中身は読めない）
  • <form> の送信によるページ遷移（だから CSRF 対策が別途必要）
  • fetch(url, { mode: "no-cors" }) … 送れるが、返ってくるのは中身が見えない opaque レスポンス
