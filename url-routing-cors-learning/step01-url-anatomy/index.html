STEP 01

URL の構造を分解する

ルーティングも CORS も、すべて「URL のどの部分を見ているか」の話です。まずは部品の名前を覚えましょう。

1. URL の部品

  https://user:pass@example.com:8080/shop/items/42?color=red&size=M#reviews
  └─┬──┘   └───┬───┘ └────┬────┘└┬─┘└──────┬─────┘└──────┬───────┘└──┬───┘
 protocol  認証情報    hostname  port   pathname         search       hash
           └──────────── host ─────────┘
  └──────────── origin ─────────────────┘ ← protocol + host（ポート込み）
pathnameサーバーが「どのページか」を判断する部分 → サーバーサイドルーティング / History API ルーティング（STEP 3, 5）
search（クエリ）?key=value&... 形式でページに追加情報を渡す（STEP 2）
hash（フラグメント）サーバーに送信されない。ブラウザ内だけで使う → ハッシュルーティング（STEP 4）
originprotocol + hostname + port。これが 1 つでも違えば「別オリジン」→ CORS（STEP 6, 7）

2. URL オブジェクトで分解してみる

好きな URL を入力してください。new URL(文字列) が自動で分解します。

// コード
const url = new URL(input.value);
url.protocol  // "https:"
url.hostname  // "example.com"
url.port      // "8080"（既定ポートなら ""）
url.pathname  // "/shop/items/42"
url.search    // "?color=red&size=M"
url.hash      // "#reviews"
url.origin    // "https://example.com:8080"

// 相対パスは「基準 URL」を第 2 引数に渡すと解決できる
new URL("/relative/path?x=1", location.origin);

3. いま開いているページの URL = location

window.location は「現在のページの URL」を表す、URL オブジェクトとほぼ同じプロパティを持つオブジェクトです。

?from=step1&n=1#section-a に移動 #section-b だけ変更 クエリとハッシュを消す

「#section-b だけ変更」ではページがリロードされず、popstate → hashchange の順にイベントが発生します（下の時刻が変わらない）。ページ読み込み時刻:

4. JavaScript で URL を変える 3 つの方法

location.href = "/other?x=1";           // ① 移動（サーバーへリクエスト、履歴に残る）
location.hash = "#/users/1";             // ② hash だけ変更（リクエストなし。popstate → hashchange）→ STEP 4
history.pushState(null, "", "/users/1"); // ③ URL 表示だけ変更（リクエストなし）→ STEP 5
