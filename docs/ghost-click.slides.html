React / タッチ UI

Ghost Click を
理解して潰す

canvas をタップしたら、開いたばかりのダイアログの「削除」が勝手に押された。
その仕組みと、7 つの対策。

react-ghost-click-poc · React 18 + TypeScript + Playwright

現象

タップ 1 回で「削除」が実行される

STEP 1

canvas 上のパーツをタップ

pointerup でヒットテストし、パーツを選択する。ドラッグ系 UI でよくある実装。

STEP 2

指の真下にダイアログが開く

同期的に showModal()。先頭の「削除」ボタンがちょうどタップ位置に重なる。

STEP 3

触っていない「削除」が実行される

ダイアログは一瞬で閉じ、パーツが消える。ユーザーは 1 回しかタップしていない。

マウスでは起きない。タッチ端末（スマホ、タブレット、タッチパネル PC）だけで起きる。

仕組み

タップ 1 回で 7 つのイベントが飛ぶ

pointerdown▶ touchstart▶ pointerup▶ touchend▶ mousedown▶ mouseup▶ click

ポインタ / タッチイベント

指の動きそのもの。ターゲットは指を下ろした要素に固定される。

互換マウスイベント

タッチ非対応ページを動かすためにブラウザが後から生成する。touchend の後に、タッチ座標を改めてヒットテストして送り先が決まる。

後半の 3 つは Touch Events 仕様の「compatibility mouse events」。現代ブラウザでは viewport meta があれば 300ms 遅延なしで touchend 直後に来る。

仕組み

click の送り先は「いつ」決まるか

マウス

click のターゲットは mousedown と mouseup の共通祖先。DOM が変わっても送り先は変わらない。

pointerup でダイアログを開いても、click は canvas に落ちる。

→ 安全

タッチ

互換 click は touchend の後に改めてヒットテストされる。pointerup で DOM を変えると、変わった後の要素に落ちる。

指の真下に現れたボタンが、そのまま click される。

→ ghost click

pointerup で同期的に UI を変える ＋ 新しい要素が指の真下にある ＝ ghost click

ポイントは「同期的」。React 18 の discrete event の更新はイベント終了時に同期 flush されるため、pointerup の setState でも互換 click が来る前に DOM が変わる。

再現

POC の再現条件

01

canvas の onPointerUp でヒットテストし、<dialog> を showModal() で同期的に開く（useLayoutEffect）

02

タップ位置に出るコンテキストメニュー風ダイアログ。先頭の「削除」ボタンの中心をタップ座標に合わせる

03

viewport meta と touch-action: manipulation で、旧来の 300ms click 遅延が無い現代ブラウザ標準の状態

画面中央のモーダルでも、ボタンがたまたま指の下にあれば同じことが起きる。再現を確実にするためタップ位置に置いている。Playwright の page.touchscreen.tap() は互換 click まで生成するので、CI で再現を固定できる。

対策

対策は 3 系統 7 種類

A. 発生させない

互換 click を作らせない、または ghost が存在しない位置で開く

1. touchend で preventDefault()
2. pointerup ではなく click で開く

B. タイミングをずらす

互換 click が canvas に落ちきってからダイアログを開く

3. setTimeout(400ms) 後に開く
4. 互換 click を 1 回待ってから開く

C. 届いても無害化

ghost が来ることを前提に、受け側で捨てる

5. ダイアログ側の時間ガード
6. 透明シールドで吸収
7. pointerdown と click の整合性チェック

POC ではプルダウンで切り替えられ、すべて Playwright で「ghost で削除されない」「本物のタップは動く」を確認済み。

対策 A

1. touchend で preventDefault()

const onPointerUp = (e) => {
  if (hit) {
    openDialog(part);
    openedDuringTouch.current = true;
  }
};
const onTouchEnd = (e) => {
  if (openedDuringTouch.current) {
    e.preventDefault(); // 互換 click を作らせない
  }
  openedDuringTouch.current = false;
};

Touch Events 仕様の正攻法。touchend を preventDefault すると mousedown / mouseup / click が生成されない。

ログ: click が存在しないpointerup → canvas
note ダイアログを開く
touchend → canvas
（以降なし）

React の onTouchEnd は非 passive で登録されるので効く（touchstart / touchmove / wheel は passive）。開いたタップでだけ呼ぶこと。pointerup の preventDefault では click は止まらない。

対策 A

2. pointerup ではなく click で開く

// before
<canvas onPointerUp={openIfHit} />

// after
<canvas onClick={openIfHit} />

// click はイベント列の最後。
// この後に来る ghost は存在しない。

タップ列の最後のイベントで開けば、ダイアログが現れた後に飛んでくる互換イベントはない。最も単純。

ログ: click は canvas に落ちるtouchend → canvas
mousedown → canvas
click touch → canvas
note ダイアログを開く

ドラッグ操作を持つ canvas は pointerup で状態を確定させたいことが多く、click に寄せられない場合がある。

対策 B

3・4. 開くのを互換 click の後にずらす

3. setTimeout(400ms)

const onPointerUp = () => {
  if (hit) setTimeout(open, 400);
};

単純で確実。ただし体感遅延が出て、マウスでも同じだけ待たされる。400ms は旧来の 300ms 遅延 + α の経験則。

4. 互換 click を 1 回待つ

window.addEventListener("click",
  () => setTimeout(open, 0),
  { capture: true, once: true });
setTimeout(open, 400); // fallback

click のディスパッチ完了を待ってから開く。マウスなら遅延ほぼゼロ。click が来ない場合（touchcancel 等）はタイムアウトで開く。二重に open しないようフラグでガードする。

2.5ms pointerup → canvas · 7.6ms click touch → canvas · 19.9ms note ダイアログを開く（対策 4 の実測）

対策 C

5. ダイアログ側の時間ガード

useLayoutEffect(() => {
  const openedAt = performance.now();
  const guard = (e) => {
    if (performance.now() - openedAt < 500) {
      e.stopPropagation();
      e.preventDefault();
    }
  };
  el.addEventListener("click", guard, true);
  return () => el.removeEventListener("click", guard, true);
}, []);

ダイアログ要素に capture 段階のネイティブリスナーを付け、開いた直後の click を握りつぶす。

React の onClick は root で bubble を待っているので届かない。共通ダイアログにフック 1 行で済む。

トレードオフ本物の高速な 2 タップ目も一定時間無視される。閾値はヒューリスティック。

対策 C

6. 透明シールドで最初の click を吸収

<dialog>
  {shield && (
    <div className="click-shield"
      onClick={(e) => {
        e.stopPropagation();
        setShield(false);
      }} />
  )}
  <button>削除</button>
</dialog>

.click-shield { position: fixed; inset: 0; }

全画面の透明要素を最前面に置き、最初の click を吸収して自身を消す（タイムアウト付き）。ghost がどこに落ちても安全。

top layer の罠showModal() した <dialog> は top layer にあり、通常の z-index では上に置けない。シールドは dialog の子として描画する。

マウスでは ghost が来ないためタイムアウトまでシールドが残る。pointerType で出し分けると改善できる。backdrop クリックで閉じる light dismiss の誤発火も防げる。

対策 C

7. pointerdown と click の整合性チェック

let down = null;
window.addEventListener("pointerdown",
  (e) => { down = e.target; }, true);
window.addEventListener("click", (e) => {
  if (e.detail === 0) return;      // keyboard
  if (!down?.isConnected) return;  // 差し替え済み
  if (!e.target.contains(down)) {
    e.stopImmediatePropagation();
    e.preventDefault();            // ghost
  }
}, true);

マウスの規則「click のターゲットは pointerdown ターゲットの祖先」をタッチにも適用する。祖先でなければ ghost。

アプリ全体で 1 箇所。canvas にもダイアログにも手を入れない。

トレードオフpointerdown 後に DOM が差し替わる UI で誤検知しうる。差し替えで外れた場合は isConnected で素通し。detail === 0 はキーボードや element.click() 由来なので対象外。

比較

7 つの対策を並べる

対策ghost click変更箇所主なトレードオフ
1. touchend で preventDefault()発生しないcanvas非 passive 必須。開いた時だけ呼ぶ
2. click で開くcanvas に落ちるcanvasドラッグ系 UI では使いにくい
3. setTimeout(400ms)canvas に落ちる開く側体感遅延。マウスでも待たされる
4. 互換 click を待つcanvas に落ちる開く側実装がやや複雑。タイムアウト管理
5. 時間ガード届くがブロックダイアログ高速な本物の 2 タップ目も無視
6. 透明シールドシールドが吸収ダイアログdialog の子に置く。マウスでは残留
7. 整合性フィルタ届くがブロックアプリ全体DOM 差し替え UI で誤検知の可能性

「発生しない」は 1 だけ。2〜4 は発生するが無害な場所に落ちる。5〜7 は発生してダイアログ側に届くが実害を防ぐ。

選び方

どこに手を入れられるかで決める

新規に書ける1 か 2

touchend の preventDefault、または click で開く。原因そのものを断つので副作用が最も少ない。

ダイアログが共通コンポーネント5 か 6

開く側が多数あるなら、受け側のダイアログに時間ガードかシールドを入れて一括で守る。

既存アプリに横断適用7

開く側もダイアログも触らずに window で 1 箇所。誤検知の可能性は把握した上で。

最後の手段3 か 4

遅延型は仕組みが分かりやすい反面、体感に影響する。他が使えないときに。

複数を併用しても問題ない。例えば 1 を基本にしつつ、共通ダイアログに 5 を保険として入れる。
