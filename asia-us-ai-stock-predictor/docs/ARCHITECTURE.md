# アーキテクチャ

## 全体像

アジア（東京/ソウル）→ 欧州 → 米国という市場の時間順序を利用し、
アジア・欧州市場の引け後に「当日±2σ以上動いた先行銘柄」を検出して、
対応する米国 AI 関連銘柄の統計的な反応見込みを提示するツール。

## バックエンド言語の選定

**Python (FastAPI) を採用**。理由:

- 分析層の本体が pandas/numpy に強く依存する（ラグ相関・ローリング統計・回帰）
- yfinance が Python ネイティブで、時間外データ・curl_cffi によるブラウザ偽装まで面倒を見てくれる
- Node でやる場合、データ取得と統計処理の両方を自前実装することになり工数が数倍になる

フロントエンドのロジック（チャート整列・正規化・表示用変換）は TypeScript の純関数として
切り出し、Vitest でテストする。

## データモデルと時間軸の扱い

すべての日足は **取引所ローカル日付** でインデックスされる。市場の時間順序
（JST: 東京/ソウル 9:00–15:30 → 欧州 16:00–24:30 → 米国 22:30–翌5:00）により、
**同一カレンダー日付 t のアジア引けは、同じ t の米国セッション開始より先行**する。

- ラグ 0: アジア(t) → 米国(t) … 主検証対象（同日波及）
- ラグ +1: アジア(t) → 米国(t+1)
- ラグ −1: 米国(t−1) → アジア(t) … 支配的な「米国→アジア」方向。
  これとの比較で「アジア発の固有材料」かどうかを切り分ける

### 織り込み度の定義

米国銘柄の当日リターンを 2 つに分解する:

- **ギャップ（織り込み済み分）**: `open(t) / close(t−1) − 1` … 時間外・先物で
  既に織り込まれた分。プレマーケット時間足が取得できる場合はアジア引け時点の
  プレマーケット価格でさらに精緻化
- **残余リターン**: `close(t) / open(t) − 1` … 寄り付き後に取れた分。
  シグナルの実用価値はここで評価する

### ベータ分解

`r_us(t) = α + β·r_spx(t) + ε(t)` をローリング 120 日で回帰し、
残差 ε をペア固有リターンとして条件付き分析に使う。市場全体の連れ高/連れ安を除いた
「純粋なペア効果」を測る。

## シグナル強度の判定基準

| 強度 | 条件 |
|------|------|
| strong | 条件付きヒット率 ≥ 65% かつ サンプル数 ≥ 10 かつ 残余リターンの符号一致 |
| moderate | ヒット率 ≥ 55% かつ サンプル数 ≥ 10 |
| weak / none | 上記未満、またはサンプル不足 |

閾値はすべて `config/watchlist.json` の `analysis` セクションで変更可能。

## エラーハンドリング・レート制限

- `DataService` がソースのリストを順に試すフォールバックチェーン
  （yfinance → stooq → キャッシュのみ）
- リクエスト間スロットリング（既定 0.5 秒）+ 指数バックオフのリトライ（2s/4s/8s）
- 取得失敗時はキャッシュ済みデータで分析を継続し、レスポンスに `stale: true` を付与
- 注意: 2026-06 時点で stooq.com はサーバーサイドからのアクセスに PoW チャレンジを
  課しており利用不可。実装は残してあるが既定では無効。yfinance が一次ソース

## API 契約（フロントエンド ↔ バックエンド）

- `GET /api/watchlist` … レイヤー・銘柄・ペア定義
- `GET /api/heatmap?window=120&lag=0` … レイヤー別相関マトリクス
- `GET /api/pair/{asia}/{us}/lags` … ラグ −3..+3 の相関プロファイル + ローリング相関系列
- `GET /api/pair/{asia}/{us}/overlay?days=250` … 時差補正済み重ね合わせ系列（正規化済み）
- `GET /api/pair/{asia}/{us}/backtest` … 条件付き分析・織り込み分解の過去成績
- `GET /api/signals/today` … 当日シグナル一覧
- `POST /api/data/refresh` … キャッシュ差分更新
