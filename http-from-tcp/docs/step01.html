step01: TCPエコーサーバ

まだHTTPは1行も書きません。まず土台を見ます。

このステップでわかること
  • TCPは「バイト列を運ぶ土管」でしかない
  • HTTPリクエストとは、決まった形のテキストをTCPに書き込むこと
  • ブラウザが期待しているのは「HTTPの応答」であって、TCPの返事ではない

使うもの

import net from "node:net";   // これだけ。HTTPライブラリは使いません

TCPとHTTPの関係

ブラウザ / curl あなたのサーバ │ │ │ ①TCP接続を確立（3ウェイハンドシェイク） │ │ ────────────────────────────────────→ │ │ │ │ ②バイト列を書き込む │ │ ────────────────────────────────────→ │ net の world はここまで。 │ "GET / HTTP/1.1\r\n..." │ 中身が何かは一切知らない │ │ │ ③バイト列が返ってくる │ │ ←──────────────────────────────────── │ │ │ │ ④接続を閉じる │ │ ←───────────────────────────────────→ │
HTTPは「TCPの上を流れるテキストの取り決め」

TCPは「順番どおりに、欠けずにバイト列を届ける」ことだけを保証します。 どこからどこまでが1つのメッセージなのか、それが何を意味するのかは まったく知りません。それを決めているのがHTTPです。

コードの中身

const server = net.createServer((socket) => {
  // TCP接続が来たら呼ばれる。HTTPのことは何も知らない。

  socket.on("data", (chunk) => {
    // 相手が送ってきたバイト列が、届いた分だけ何度でもここに来る
    console.log(visualize(chunk));

    socket.write(chunk);   // そのまま送り返す（エコー）
  });
});

server.listen(8080);

見やすくするための道具

function visualize(buf) {
  return buf.toString("utf8")
    .replace(/\r/g, "\\r")     // 画面では見えない制御文字を
    .replace(/\n/g, "\\n\n");  // 文字として書き出す
}

これをやると「HTTPは \r\n で行を区切るテキスト」が一目でわかります。

手を動かす

起動

cd steps/step01-tcp-echo
node server.js

実験1: TCPはただの土管

nc localhost 8080

hello と打ってEnter。そのまま返ってきます。 「メソッド」も「ヘッダー」も「ステータスコード」も存在しません。

実験2: curlが送っているものを覗く

curl -v http://localhost:8080/hello

サーバのコンソールにこう出ます。

GET /hello HTTP/1.1\r\n
Host: localhost:8080\r\n
User-Agent: curl/8.7.1\r\n
Accept: */*\r\n
\r\n

これがHTTPリクエストの正体です。

実験3: ブラウザで開く

http://localhost:8080 を開くと ERR_EMPTY_RESPONSE などになります。それで正解です。 HTTPの応答を返していないからです。

読み取れること

見えたもの意味
GET /hello HTTP/1.11行目だけが特別。「リクエストライン」
\r\n行の区切り。\n ではない
最後の \r\n\r\n空行。ヘッダーの終わりの合図
Host: など「名前: 値」の並び＝ヘッダー
1回の data イベント ＝ 1メッセージ ではない

TCPは「1回のwriteが1回のdataで届く」ことを保証しません。 大きなリクエストは分割して届きます。step03 でこの問題に対処します。

クイズ: なぜ改行が \n ではなく \r\n なのか？

HTTPはテレタイプ端末の時代の慣習を引き継いだテキストプロトコルだからです。 \r（キャリッジリターン＝印字位置を左端へ）と \n（ラインフィード＝紙を1行送る）の2動作をセットで送っていた名残です。 同じ理由でSMTPやFTPも \r\n を使います。

実装上の注意: \n だけで区切るサーバも多いですが、 厳密には \r\n です。この教材では常に \r\n を使います。

クイズ: ヘッダーの終わりはどうやって表現されていましたか？

空行（\r\n\r\n）です。 これがHTTPで最も重要なルールのひとつで、step02〜05 で繰り返し出てきます。
