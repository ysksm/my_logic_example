step15: Access-Control-Max-Age

プリフライトのキャッシュ。2回目から OPTIONS が消えるのを目で見ます。

問題意識
API を1回呼ぶ = OPTIONS の往復 + 本番の往復 = 2往復 APIを100回呼べば、OPTIONS も100回飛ぶ

プリフライトは往復1回分まるごと余計な通信です。 レイテンシの大きい回線では体感できるほど遅くなります。

Access-Control-Max-Age: 30

「この許可は30秒間有効です」と伝えると、ブラウザは同じ条件のプリフライトをスキップします。

手を動かす

cd steps/step15-max-age
node server.js

2つのボタンは、どちらも「PUT を3回連続で送る」だけです。 違いはサーバが Access-Control-Max-Age を返すかどうかだけ。

パスMax-AgeOPTIONS本番
/api/nocache無し33
/api/cached3013

本番はどちらも3回。OPTIONS の回数だけが違います。

DevTools の Network タブでも OPTIONS の行数を数えてみてください。 /api/cached では1本目にだけ OPTIONS があります。

30秒待ってからもう一度押すと、/api/cached にも OPTIONS が飛びます。 キャッシュが切れたためです。

キャッシュの単位

キャッシュのキー ＝ オリジン ＋ URL ＋ メソッド ＋ ヘッダーの組み合わせ ＋ credentialsの有無
  • /api/cached への PUT がキャッシュされていても、 DELETE は別扱いで改めてプリフライトが飛ぶ
  • URLが1文字でも違えば別扱い
  • credentials の有無でも別扱い

つまり「1回プリフライトを通せば全部通る」わけではありません。

ブラウザごとの上限

ブラウザ上限
Chrome7200秒（2時間）
Firefox86400秒（24時間）
Safari600秒

Access-Control-Max-Age: 86400 と書いても、Chromeでは2時間に丸められます。

実務での注意

開発中に大きな Max-Age を設定すると、設定を直しても反映されない

ブラウザが古い許可を覚えているためです。 「CORS設定を直したのに直らない」の犯人はたいていこれです。

対処

  • DevTools の Network タブで Disable cache を有効にする
  • ブラウザを再起動する
  • 開発中は Max-Age を小さく（または付けない）
状況目安
開発中付けない、または 0〜10
本番・安定したAPI600〜7200
クイズ: /api/x への PUT のプリフライトがキャッシュされているとき、 /api/x への DELETE はプリフライトなしで送れる？

送れません。 キャッシュはメソッドごとに分かれています。改めてプリフライトが飛びます。

クイズ: サーバ側のカウンタをリセットすれば、次はまた OPTIONS が飛びますか？

飛びません。 キャッシュを持っているのはブラウザです。 サーバ側の数字をリセットしても、ブラウザの記憶は消えません。 CORSがブラウザ側の仕組みであることが、ここでも効いています。
