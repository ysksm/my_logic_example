step06: GET

第2章のはじまり。HTTPコアは以降変わりません。変わるのはアプリ部分だけです。

このステップでわかること
  • クエリ文字列のパース（パーセントエンコーディング、+ の罠）
  • ルーティングの正体は「パスを見て分岐するだけ」
  • GETは安全（safe）であるべき、という原則

URLの構造

http://localhost:8080/search?q=%E7%8A%AC&page=2#top └─┬─┘ └───┬────┘└──┬──┘└──────┬───────┘└┬┘ スキーム ホスト:ポート パス クエリ文字列 フラグメント ↑ ブラウザ内部だけ。サーバには送られない

リクエストラインに載るのは パス + クエリ の部分だけです。

GET /search?q=%E7%8A%AC&page=2 HTTP/1.1
Host: localhost:8080
フラグメント（#top）はサーバに届かない

「ページ内のどこを表示するか」はブラウザだけの関心事です。 サーバのログに # 以降が出てこないのはこのためです。

クエリ文字列のパース

function parseQuery(qs) {
  const out = {};
  for (const pair of qs.split("&")) {
    const eq = pair.indexOf("=");
    const rawName  = eq === -1 ? pair : pair.slice(0, eq);
    const rawValue = eq === -1 ? ""   : pair.slice(eq + 1);

    // クエリ文字列では + が半角スペースを意味する（歴史的仕様）
    const decode = (s) => decodeURIComponent(s.replace(/\+/g, " "));

    const name = decode(rawName), value = decode(rawValue);

    // 同じ名前が複数回出ることがある → 配列で持つ
    if (name in out) out[name] = [].concat(out[name], value);
    else out[name] = value;
  }
  return out;
}
場所+ の意味空白の書き方
クエリ文字列半角スペース+ または %20
パスプラス記号そのもの%20 のみ

混乱の元ですが、実装では場所によってデコード方法を変える必要があります。

手を動かす

cd steps/step06-get
node server.js

ブラウザで http://localhost:8080/ を開いてください。

実験1: GETの入力はすべてURLに載る

フォームに「柴 犬」と入れて送信すると、アドレスバーが /search?q=%E6%9F%B4+%E7%8A%AC&page=2 に変わります。

だからGETでパスワードを送ってはいけない
  • ブラウザの履歴に残る
  • サーバのアクセスログに残る
  • Refererヘッダーで他サイトに漏れることがある

実験2: パーセントエンコーディング

curl 'http://localhost:8080/search?q=%E7%8A%AC&page=2'    # → 犬
curl 'http://localhost:8080/search?tag=a&tag=b&tag=c'      # → 配列
curl 'http://localhost:8080/search?q=a+b'                  # → "a b"
curl 'http://localhost:8080/items/a+b'                     # → "a+b"

実験3: GETで状態を変えるとどうなるか

/danger をブラウザで開き、リロードしてみてください。カウンタが増えます。

安全（safe）と冪等（idempotent）

メソッド安全冪等意味
GET○○取得するだけ
POST××送りつける（結果はサーバ次第）
PUT×○このURLの中身を置き換える
DELETE×○このURLのものを消す
  • 安全 = サーバの状態を変えない
  • 冪等 = 1回でも100回でも、最終的な状態が同じ
GETで状態を変えると起きること
  • ブラウザやプロキシがキャッシュする → 2回目は実行されない
  • ブラウザがリンクを先読み（prefetch）する → 押していないのに実行される
  • クローラが全リンクを踏む → 「削除リンク」を全部踏まれる
クイズ: ?q=a+b と ?q=a%20b の結果は同じ？

クエリ文字列の中では同じです（どちらも "a b"）。 ただしパスの中では違います。/items/a+b の + はプラス記号のままです。
