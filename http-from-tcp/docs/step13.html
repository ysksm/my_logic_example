step13: 単純リクエストと ACAO

たった1行のヘッダーで通る場合と、通らない場合がある。その境界線を正確に知ります。

このステップでわかること
  • Access-Control-Allow-Origin（ACAO）は「有無」ではなく「一致」で判定される
  • 「単純リクエスト」の正確な条件
  • 条件を外れると、ブラウザが勝手に OPTIONS を送る（→ step14）

やりとり

→ GET /api/wildcard HTTP/1.1
   Host: localhost:8081
   Origin: http://localhost:8080      ← ブラウザが自動で付ける

← HTTP/1.1 200 OK
   Access-Control-Allow-Origin: *     ← サーバの「読ませてよい」宣言
   Content-Type: application/json

   {"message":"..."}
2つのヘッダーの役割
  • Origin … ブラウザが付ける。「このリクエストはどのページから出たか」
  • Access-Control-Allow-Origin … サーバが付ける。「このオリジンには読ませてよい」

ブラウザは応答を受け取ってから ACAO を見て、 JSに渡すかどうかを決めます。判定はすべてブラウザ側で行われます。

実験A: GET（単純リクエスト）

cd steps/step13-simple-request
node server.js
ボタンACAO結果
① /api/no-cors無し失敗
② /api/wildcard*成功
③ /api/wrong-originhttps://example.com失敗
③ が重要です

ヘッダーはあるのに失敗します。
CORSの判定は「ヘッダーが有るか無いか」ではなく 「値がこのページのオリジンと一致するか」です。 * は「すべてに一致する特別な値」というだけ。

実験B: POSTはContent-Typeで結果が変わる

同じ /api/wildcard（ACAO: *）に、同じPOSTを送ります。

ボタンContent-Type結果サーバに届いたもの
④text/plain成功POST /api/wildcard
⑤application/json失敗OPTIONS /api/wildcard

サーバのコンソールを比べてください。 ⑤ では POST が届かず、代わりに OPTIONS が届いています。

これがプリフライトです

application/json は「単純リクエスト」の条件から外れるため、 ブラウザが本番の前に許可を確認しに行きました。 このステップのサーバはまだ OPTIONS に応答しないので失敗します（step14で対応）。

「単純リクエスト」の条件

次をすべて満たすときだけ、プリフライトなしで送られます。

項目条件
メソッドGET / HEAD / POST のいずれか
ヘッダー手で付けたヘッダーが安全なもの（Accept, Accept-Language, Content-Language, Content-Type, Range など）だけ。
Authorization や X-独自ヘッダー を1つでも付けると外れる
Content-Typeapplication/x-www-form-urlencoded / multipart/form-data / text/plain のいずれか
application/json は含まれない
その他アップロード進捗イベントを使っていない、 ReadableStream をボディにしていない
なぜこの条件なのか

この条件は「HTMLのフォームで昔から送れたもの」とほぼ一致します （step07 のクイズを思い出してください）。
フォームで送れる範囲はCORSが生まれる前から送れていたので、 いまさら事前確認を要求しても意味がありません。 それを超えるもの（PUT、DELETE、JSON、独自ヘッダー）だけ 確認を求める、という設計です。

ただし「送れる」だけで「読める」わけではありません。 応答を読むには、いずれの場合も ACAO が必要です。

* と個別指定

値使う場面
Access-Control-Allow-Origin: * 誰でも使ってよい公開API。Cookieや認証情報を伴わないもの
Access-Control-Allow-Origin: https://app.example.com 特定のフロントからだけ使わせたいAPI
step16 の予告

* は credentials（Cookie）と 併用できません。ブラウザが明確に拒否します。理由は step16 で。

curlで確かめる

curl -i -H 'Origin: http://localhost:8080' http://localhost:8081/api/wildcard

ACAO が返っています。curl はこのヘッダーを見ても何もしません。 判断するのはブラウザだけです。

クイズ: ACAO が https://example.com のとき、 http://localhost:8080 のページは読める？

読めません。 ヘッダーの有無ではなく一致で判定されます。 「CORSヘッダーは付けたのに直らない」というとき、まず値を確認してください。
