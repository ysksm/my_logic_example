step10: Cookie の往復

HTTPは「前回のことを覚えていない」プロトコル。それを回避する仕組み。

このステップでわかること
  • サーバは何も覚えていない。覚えているのはブラウザ
  • Set-Cookie と Cookie は形が違う
  • Cookieの値はクライアントが自由に書き換えられる

Cookieの仕組み

1回目 → GET / HTTP/1.1 ← HTTP/1.1 200 OK Set-Cookie: visits=1; Path=/ ← 「これを持っておいて」 2回目（ブラウザが勝手に付ける） → GET / HTTP/1.1 Cookie: visits=1 ← 「持っています」 ← HTTP/1.1 200 OK Set-Cookie: visits=2; Path=/ ← 「更新して」

サーバは訪問回数を覚えていません。 ブラウザが持ってきた数字に1を足して返しているだけです。

Cookieを保持するのはクライアントの機能

HTTPの必須機能ではありません。 curl は既定でCookieを保存しないので、何度叩いても「1回目」です。

2つのヘッダーは形が違う

ヘッダー形個数
サーバ → ブラウザSet-Cookie 名前=値; 属性; 属性1つのCookieにつき1行
ブラウザ → サーバCookie 名前=値; 名前=値全部まとめて1行
← Set-Cookie: visits=3; Path=/
← Set-Cookie: first_seen=2026-01-01; Path=/

→ Cookie: visits=3; first_seen=2026-01-01

リクエスト側には属性が付いてきません。 ブラウザは Path や HttpOnly を自分で使うだけで、 サーバには送り返しません。

Set-Cookie は連結してはいけない唯一のヘッダー

step03 で「同名ヘッダーは , で連結」と書きましたが、 Set-Cookie だけは例外です（値の中に , を含みうるため）。 step05 の res.send が配列を受け取れるようにしてあるのはこのためです。

res.send(200, { "Set-Cookie": ["a=1; Path=/", "b=2; Path=/"] }, body);

手を動かす

cd steps/step10-cookie
node server.js

実験1: ブラウザでリロード

http://localhost:8080/ を何度もリロード。数字が増えます。
DevTools → Network でこのリクエストを選び、 Request Headers の Cookie と Response Headers の Set-Cookie（2行）を見比べてください。

実験2: curlはCookieを覚えない

curl -s http://localhost:8080/whoami   # → visits:1
curl -s http://localhost:8080/whoami   # → visits:1

実験3: curlに覚えさせる

rm -f jar.txt
curl -s -c jar.txt -b jar.txt http://localhost:8080/whoami
curl -s -c jar.txt -b jar.txt http://localhost:8080/whoami
cat jar.txt

-c が保存、-b が送信。jar.txt の中身は ブラウザが内部で持っているものと同じ情報です。

実験4（重要）: 手でCookieを送る

curl -s -H 'Cookie: visits=999' http://localhost:8080/whoami   # → 1000

Cookieの値は信用できない

クライアントが自由に書き換えられる
Cookie: is_admin=true
Cookie: user_id=1
Cookie: price=0

こうした値をそのまま信用してはいけません。 ブラウザのDevToolsからでも、curlからでも、いくらでも変更できます。

答えは step11 のセッションID方式

Cookieには推測できない「鍵」だけを入れ、 中身（誰なのか）はサーバ側に置きます。

Cookieを消す

Set-Cookie: visits=; Max-Age=0; Path=/

「削除」という命令はありません。 寿命ゼロのCookieを送りつけると、ブラウザが捨てます。

クイズ: 値に ; や日本語を入れたいときは？

encodeURIComponent() でエンコードします。 Cookieの値には ; , 空白などをそのまま入れられません。 サンプルの first_seen はエンコードしてから入れています。
