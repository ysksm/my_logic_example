# step03: ヘッダーをパースする

## step02からの差分

- **バッファに溜める**（TCPはデータが分割して届く。1回の `data` で全部揃う保証はない）
- `\r\n\r\n` を見つけるまで待ち、揃ったら2行目以降を `名前: 値` に分解する
- ヘッダー名を**小文字に正規化**する（HTTPのヘッダー名は大文字小文字を区別しない）

## 起動

```sh
node server.js
```

## 実験1 — curlが送るヘッダーとブラウザが送るヘッダー

```sh
curl http://localhost:8080/
```

curl は3〜4個しか送りません。次にブラウザで `http://localhost:8080/` を開いてください。
`sec-ch-ua`、`accept-encoding`、`sec-fetch-mode`、`user-agent` …と10個以上並びます。

**わかること:** ヘッダーは「メッセージに付ける自由なメタデータ」。
数も種類も決まっていません。

## 実験2 — 大文字小文字は区別されない

```sh
curl -H 'X-Foo: 1' -H 'x-FOO: 2' http://localhost:8080/
```

結果は `x-foo : 1, 2` と1つにまとまります。

**わかること:**
- ヘッダー名の大文字小文字に意味はない（`Content-Type` と `content-type` は同じ）
- 同名ヘッダーが複数ある場合は `,` で連結するのがHTTPの規則
- そのため実装ではふつう**小文字に正規化した辞書**で持つ

## 実験3 — ヘッダーが分割して届く様子を見る

`nc` で1行ずつゆっくり送ってみます。

```sh
{ printf 'GET /slow HTTP/1.1\r\n';
  sleep 1; printf 'Host: localhost\r\n';
  sleep 1; printf 'X-Late: yes\r\n';
  sleep 1; printf '\r\n'; } | nc localhost 8080
```

サーバのコンソールに

```
▶ まだ \r\n\r\n が来ていません。続きを待ちます
```

が何度か出てから、最後にまとめて解析されます。

**わかること:** これが「バッファに溜める」理由です。
`socket.on('data')` が来た＝1メッセージ届いた、ではありません。

## 実験4 — Host ヘッダー

```sh
curl -H 'Host: example.com' http://localhost:8080/
```

`host = example.com` と表示されます。接続先は localhost なのに。

**わかること:** `Host` は「どのサイト宛か」をサーバに伝えるだけのヘッダー。
1つのIP・ポートで複数サイトを運用できるのはこれのおかげ（バーチャルホスト）。
HTTP/1.1 では必須です。
