# step06: GET

## step05からの差分

**HTTPコアは変更ありません。** 変わるのはアプリケーション部分だけです。

- `parseQuery()` — クエリ文字列を辞書に分解する
- パスで処理を振り分ける簡易ルーター
- GET は「安全（safe）」であるべき、という原則

## 起動

```sh
node server.js
```

ブラウザで `http://localhost:8080/` を開いてください。

## 実験1 — クエリ文字列はURLの一部

トップページのフォームに「柴 犬」と入れて送信すると、アドレスバーが変わります。

```
/search?q=%E6%9F%B4+%E7%8A%AC&page=2
```

**わかること:** GETで送ったデータは**すべてURLに載る**。だから
- ブラウザの履歴に残る
- アクセスログに残る
- 人に共有できる（URLをコピーすれば同じ結果が見られる）

パスワードをGETで送ってはいけない理由がこれです。

## 実験2 — パーセントエンコーディング

```sh
curl 'http://localhost:8080/search?q=%E7%8A%AC&page=2'
```

`%E7%8A%AC` が `犬` になります。UTF-8の3バイトを `%XX` で1バイトずつ書いたものです。

URLで使える文字は限られている（ASCIIの一部だけ）ので、それ以外はこの形に変換します。

## 実験3 — `+` は空白（クエリ文字列の中だけ）

```sh
curl 'http://localhost:8080/search?q=a+b'      # → "a b"
curl 'http://localhost:8080/items/a+b'         # → "a+b"
```

| 場所 | `+` の意味 | 空白の書き方 |
|---|---|---|
| クエリ文字列 | 半角スペース | `+` または `%20` |
| パス | プラス記号そのもの | `%20` のみ |

歴史的経緯によるもので、混乱の元です。実装では場所によってデコード方法を変える必要があります。

## 実験4 — 同じ名前のパラメータ

```sh
curl 'http://localhost:8080/search?tag=a&tag=b&tag=c'
```

```json
"tag": ["a", "b", "c"]
```

**わかること:** クエリパラメータは「辞書」ではなく「名前付きの並び」。
チェックボックスの複数選択などで実際に使われます。

## 実験5 — GETで状態を変えるとどうなるか

ブラウザで `/danger` を開き、リロードを何度か押してください。カウンタが増えます。

```sh
curl http://localhost:8080/danger
```

**わかること:** GETは「安全（safe）」＝サーバの状態を変えない、が原則です。
破ると次のような事故が起きます。

- ブラウザやプロキシがGETを**キャッシュ**する → 2回目は実行されない
- ブラウザがリンクを**先読み（prefetch）**する → 押していないのに実行される
- クローラが全リンクを踏む → 「削除リンク」を全部踏まれる

「削除は必ずDELETEかPOSTで」と言われるのはこのためです。

## メソッドの性質まとめ

| メソッド | 安全 (safe) | 冪等 (idempotent) | 意味 |
|---|:---:|:---:|---|
| GET | ○ | ○ | 取得するだけ |
| POST | × | × | 送りつける（結果はサーバ次第） |
| PUT | × | ○ | このURLの中身を置き換える |
| DELETE | × | ○ | このURLのものを消す |

- **安全** = サーバの状態を変えない
- **冪等** = 1回でも100回でも、最終的な状態が同じ

step07以降で残りを実装します。
