# step15: Access-Control-Max-Age

## step14からの差分

- プリフライト応答に `Access-Control-Max-Age` を付ける
- `OPTIONS` が実際に何回来たかを数えて、画面に出す

## 問題意識

プリフライトは**往復1回分まるごと余計な通信**です。

```
API を1回呼ぶ = OPTIONS の往復 + 本番の往復 = 2往復
```

APIを100回呼べば、`OPTIONS` も100回飛びます。
レイテンシの大きい回線では体感できるほど遅くなります。

## 解決

```
Access-Control-Max-Age: 30
```

「この許可は30秒間有効です」とブラウザに伝えると、
ブラウザは同じ条件のプリフライトを30秒間スキップします。

## 起動

```sh
node server.js
```

ブラウザで `http://localhost:8080/` を開いてください。

## 実験

| ボタン | エンドポイント | Max-Age |
|---|---|---|
| 左 | `/api/nocache` | 無し |
| 右 | `/api/cached` | `30` |

どちらも「`PUT` を3回連続で送る」だけです。押したあと、表の数字を見てください。

| パス | OPTIONS | 本番 |
|---|---:|---:|
| `/api/nocache` | **3** | 3 |
| `/api/cached` | **1** | 3 |

本番はどちらも3回。`OPTIONS` の回数だけが違います。

DevTools の Network タブでも `OPTIONS` の行数を数えてみてください。
`/api/cached` では1本目にだけ `OPTIONS` があります。

30秒待ってからもう一度押すと、`/api/cached` にも `OPTIONS` が飛びます。
キャッシュが切れたためです。

## キャッシュの単位

プリフライトのキャッシュは「オリジン＋URL＋メソッド＋ヘッダーの組み合わせ」で管理されます。

- `/api/cached` への `PUT` がキャッシュされていても、`DELETE` は**別扱い**
- URLが1文字でも違えば別扱い
- `credentials` の有無でも別扱い

つまり「1回プリフライトを通せば全部通る」わけではありません。

## 上限値

| ブラウザ | 上限 |
|---|---|
| Chrome | 7200秒（2時間） |
| Firefox | 86400秒（24時間） |
| Safari | 600秒 |

これを超える値を返しても、ブラウザ側の上限に丸められます。
`Access-Control-Max-Age: 86400` と書いても、Chromeでは2時間です。

## 実務での注意

**開発中に大きな `Max-Age` を設定すると、CORS設定を直しても反映されません。**
ブラウザが古い許可を覚えているためです。

「設定を直したのに直らない」と思ったら:

- DevTools の Network タブで **Disable cache** を有効にする
- ブラウザを再起動する
- 開発中は `Max-Age` を小さく（または付けない）

このステップのサーバの「カウンタをリセット」ボタンは**サーバ側の数字だけ**を
リセットします。ブラウザのプリフライトキャッシュは消せません。

## 値の選び方

| 状況 | 目安 |
|---|---|
| 開発中 | 付けない、または `0`〜`10` |
| 本番・安定したAPI | `600`〜`7200` |

CORS設定を頻繁に変える予定があるなら、短くしておくのが安全です。
