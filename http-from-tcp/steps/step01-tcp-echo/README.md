# step01: TCPエコーサーバ

## 起動

```sh
node server.js
```

## 実験1 — TCPはただの土管

別のターミナルで:

```sh
nc localhost 8080
```

`hello` と打って Enter。そのまま `hello` が返ってきます。
サーバ側のコンソールにも受信内容が出ます。

**わかること:** TCPは送られたバイト列をそのまま運ぶだけ。
「メソッド」も「ヘッダー」も「ステータスコード」も存在しません。

## 実験2 — curlが送っているものを覗く

```sh
curl -v http://localhost:8080/hello
```

サーバのコンソールにこう出ます:

```
GET /hello HTTP/1.1\r\n
Host: localhost:8080\r\n
User-Agent: curl/8.7.1\r\n
Accept: */*\r\n
\r\n
```

**わかること:** HTTPリクエストとは、この形のテキストをTCPに書き込むこと。ただそれだけ。

`curl` 側は「エコーで返ってきた `GET /hello HTTP/1.1...` はHTTPの応答として不正だ」と
判断してエラーになります。それで正解です。

## 実験3 — ブラウザで開く

`http://localhost:8080` を開くと、Chrome は
`ERR_EMPTY_RESPONSE` や `ERR_INVALID_HTTP_RESPONSE` を出します。

**わかること:** ブラウザは「HTTPの応答」を期待している。
TCPで何かを返せば良いわけではない。次のステップでその「応答」を手で書きます。

## 観察ポイント

- 1回の `curl` で `● TCP接続が確立しました` → 受信 → `● TCP接続が閉じました` の順に出る
- ブラウザでアクセスすると**接続が複数本**張られることがある（先読み接続）

- HTTPリクエストの1行目は何と何と何で構成されていましたか？
- 行の区切りに使われている2文字は何ですか？
- ヘッダーの終わりはどうやって表現されていましたか？
